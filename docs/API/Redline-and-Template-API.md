# Redline and Template API

These endpoints keep your documents, templates and knowledge base in step after a document leaves TurboDocx and comes back changed. They also turn a finished Word document into a reusable template.

## Overview

You generate a contract, send it out, and the other side returns it with edits. With this API you can:

- **Compare the returned copy** with the version TurboDocx generated, and get every change sorted by kind.
- **Apply the changes you accept.** This saves a new version of the document. You can also copy an accepted change into the template or the knowledge base entry it came from.
- **Find clause drift.** For one knowledge base entry, list the templates that follow it and the templates that hold an old, pasted copy of its text. Then swap a copy for the entry's field.
- **Make a template from a finished document.** Upload a .docx, get suggested fields, preview the result, then create the template.

### All Endpoints at a Glance

| Method | Endpoint | Description |
| ------ | -------- | ----------- |
| `POST` | `/v1/redline/reviews` | Compare a returned copy with the original |
| `POST` | `/v1/redline/reviews/:reviewId/apply` | Apply the changes you accept |
| `GET`  | `/v1/knowledge-base/:variableMapId/drift` | Check one knowledge base entry for drift |
| `POST` | `/v1/knowledge-base/:variableMapId/drift/swap` | Replace a pasted copy with the entry's field |
| `POST` | `/v1/assistant/uploads` | Upload a document to use with the endpoints below |
| `POST` | `/v1/templates/from-document/suggest` | Suggest fields for an uploaded document |
| `POST` | `/v1/templates/from-document` | Preview or create a template from an uploaded document |

## Prerequisites

- **An API key** and your **organization ID**. See [Getting Your Credentials](./Deliverable-API.md#getting-your-credentials).
- For redlines: a document you generated with TurboDocx, such as one made with [Create Deliverable](./Deliverable-API.md#endpoint-2-create-deliverable), and the edited copy that came back.
- For suggested fields: your organization's plan must include TurboDocx AI, with AI credits left.

## Authentication

Every request needs the same two headers as the rest of the API.

| Header | Value | Required | Description |
| ------ | ----- | -------- | ----------- |
| `Authorization` | `Bearer YOUR_API_TOKEN` | Yes | Your API key |
| `x-rapiddocx-org-id` | `YOUR_ORGANIZATION_ID` | Yes | Your organization ID |
| `Content-Type` | `application/json` | For JSON bodies | Leave it out for file uploads; curl's `-F` sets `multipart/form-data` for you |

:::info Use the same API key for every step
A review and an upload belong to the key that created them. Applying a review, or using an upload, with a different API key returns `404`, as if it did not exist.
:::

### Roles

| Endpoint | Roles allowed |
| -------- | ------------- |
| Compare, apply | administrator, contributor, user |
| Drift check | administrator, contributor, user |
| Drift swap | administrator, contributor |
| Upload | administrator, contributor, user, viewer |
| Suggest fields, create template | administrator, contributor, user |

A role that is not allowed gets `403` with the body `Forbidden`. When you apply a review, copying a change into a template needs administrator or contributor, and so does copying one into an org-wide knowledge base entry. A `user` can still apply the change to the document itself.

## Endpoint 1: Compare a Returned Copy

Upload the edited copy of a document you generated. TurboDocx matches it to the version it came from and lists every change.

### Endpoint

```http
POST https://api.turbodocx.com/v1/redline/reviews
```

### Request Body (multipart/form-data)

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `file` | File | **Yes** | The returned copy, as a .docx. Up to 25 MB |
| `deliverableId` | String (UUID) | No | The document this is a copy of. Only needed when TurboDocx cannot tell, for example when the copy was rebuilt in another editor |

Documents generated by TurboDocx carry a hidden reference to the exact version they came from. A copy saved in Word keeps it, so you usually send only the file. Tracked changes and direct edits are both read.

Before comparing, TurboDocx removes anything unsafe from the file, such as macros. What it removed is listed in `removed`.

### Example Request

```bash
curl -X POST "https://api.turbodocx.com/v1/redline/reviews" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -F "file=@./agreement-returned.docx"
```

### Response

`201 Created`. In this example the other side changed the fee, changed a sentence of the contract, and added a new paragraph:

```json
{
  "data": {
    "results": {
      "review_id": "b0c3babc-60c1-4e2f-b06e-109fffc62f48",
      "deliverable": {
        "id": "920a6eae-e30a-48a1-8ace-5d209d2bcd88",
        "name": "Agreement - Acme"
      },
      "changes": [
        {
          "baselineParagraphId": "body:2",
          "id": "c1",
          "class": "value",
          "kind": "direct",
          "part": "body",
          "baselineText": "The fee is 5,000 USD per month.",
          "returnedText": "The fee is 6,000 USD per month.",
          "placeholder": "{fee}",
          "before": "5,000 USD",
          "after": "6,000 USD"
        },
        {
          "baselineParagraphId": "body:3",
          "id": "c2",
          "class": "template_wording",
          "kind": "direct",
          "part": "body",
          "baselineText": "Each party shall keep the other party's confidential information secret for three years and use it only to perform this agreement.",
          "returnedText": "Each party shall keep the other party's confidential information secret for five years and use it only to perform this agreement."
        },
        {
          "afterParagraphId": "body:3",
          "id": "c3",
          "class": "new_section",
          "kind": "direct",
          "part": "body",
          "returnedText": "This agreement is governed by the laws of France.",
          "returnedStyle": ""
        }
      ],
      "removed": []
    }
  }
}
```

### Response Fields

| Field | Type | Description |
| ----- | ---- | ----------- |
| `review_id` | String | The review's ID. Send it to [Apply Changes](#endpoint-2-apply-changes) |
| `deliverable` | Object | The document this copy belongs to: `id` and `name` |
| `changes` | Array | One entry per change, in document order |
| `removed` | Array of strings | What was removed from the file as unsafe, in plain words. Empty when nothing was |

Each change has:

| Field | Type | Description |
| ----- | ---- | ----------- |
| `id` | String | The change's ID in this review: `c1`, `c2`, and so on |
| `class` | String | What kind of change it is. See the table below |
| `kind` | String | `tracked` (a tracked change in Word) or `direct` (an edit made without tracking) |
| `part` | String | Where it is: `body`, or a header, footer or other part of the file |
| `baselineText` | String | The paragraph as TurboDocx generated it. Absent for a new paragraph |
| `returnedText` | String | The paragraph in the returned copy. Absent for a deleted paragraph |
| `placeholder` | String | For a `value` change: the template field whose value changed |
| `before`, `after` | String | For a `value` change: the old and new value |
| `variableMapId` | String | For a `kb_clause` change: the knowledge base entry the clause came from |
| `baselineParagraphId`, `afterParagraphId`, `beforeParagraphId` | String | Where the change sits in the original. Used when the change is applied |
| `returnedStyle` | String | For a `new_section` change: the paragraph style it had, `""` for none |

Change classes:

| `class` | Meaning | Can be copied back to |
| ------- | ------- | --------------------- |
| `value` | A value you filled in changed, such as a name, date or amount | This document only. A template write-back is refused, because it would remove the field |
| `template_wording` | Fixed wording that came from the template changed | The template |
| `kb_clause` | A clause that came from a knowledge base entry changed | The knowledge base entry |
| `new_section` | A paragraph was added | This document only |
| `deleted_section` | A paragraph was removed | The template |

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `NoFile` | No file uploaded under field 'file'. |
| `400` | `DocumentNotDocx` | The file is not a Word document. |
| `400` | `LIMIT_FILE_SIZE` (in `code`) | File size exceeds the maximum allowed size of 25MB. Please upload a smaller file. |
| `400` | `WhichDocument` | Before I compare it, I could not tell which document this is a copy of. Which document is it? |
| `400` | `DocumentHasNewerVersion` | Before I compare it, I noticed "Agreement - Acme" has a newer version than this copy. Compare it with the newer version, or stop here? |
| `400` | `NoSavedVersions` | Before I save it, I noticed "Agreement - Acme" has no saved versions to add this copy to. Save it as a new document instead, or stop here? |
| `400` | `ValidationError` | `"deliverableId" must be a valid GUID` (in `data.errors`) |
| `403` | | `Forbidden`: your role cannot generate documents |

`WhichDocument` means the file has no reference TurboDocx can use. Send the request again with `deliverableId`. `NoSavedVersions` means the document was generated before TurboDocx kept versions, so it cannot be compared. `DocumentHasNewerVersion` means a newer version of the document was saved since this copy was made. Compare against the newer version's file instead.

## Endpoint 2: Apply Changes

Say which changes you accept. TurboDocx saves a new version of the document with them.

### Endpoint

```http
POST https://api.turbodocx.com/v1/redline/reviews/:reviewId/apply
```

### Path Parameters

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `reviewId` | String (UUID) | **Yes** | The `review_id` from [Compare a Returned Copy](#endpoint-1-compare-a-returned-copy) |

### Request Body (JSON)

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `decisions` | Array | **Yes** | 1 to 200 decisions |
| `decisions[].changeId` | String | **Yes** | A change's `id`, such as `c1` |
| `decisions[].accept` | Boolean | **Yes** | `true` to keep the change, `false` to drop it |
| `decisions[].writeBack` | String | No | Also copy the accepted change into the `template` or the knowledge base entry (`kb`). Leave it out to change this document only |

A change you do not list is dropped, the same as `"accept": false`.

### Example Request

```bash
curl -X POST "https://api.turbodocx.com/v1/redline/reviews/REVIEW_ID/apply" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "decisions": [
      { "changeId": "c1", "accept": true },
      { "changeId": "c2", "accept": true, "writeBack": "template" },
      { "changeId": "c3", "accept": true }
    ]
  }'
```

### Response

`200 OK`:

```json
{
  "data": {
    "results": {
      "deliverable": {
        "id": "94d5d915-aeb4-4ca2-b34e-9f07c2e0cb77",
        "name": "Agreement - Acme"
      },
      "applied": 3,
      "write_backs": [
        { "change_id": "c2", "target": "template", "status": "applied" }
      ]
    }
  }
}
```

### Response Fields

| Field | Type | Description |
| ----- | ---- | ----------- |
| `deliverable` | Object | The new version: `id` and `name` |
| `applied` | Number | How many accepted changes were written into the new version |
| `write_backs` | Array | One entry per accepted change you sent with `writeBack` |
| `write_backs[].change_id` | String | The change |
| `write_backs[].target` | String | `template` or `kb` |
| `write_backs[].status` | String | `applied`, `refused`, `not_allowed` or `not_supported` |
| `write_backs[].message` | String | For `refused`: why, in a sentence |

:::warning The document gets a new ID
Applying a review saves the new version as a new deliverable, with a new `id`, and retires the old one. The old `id` then returns `404`. Store the `deliverable.id` from this response. This happens even when you reject every change.
:::

The new version is built from the original TurboDocx generated plus the changes you accepted. It is not the returned file, so anything you dropped stays out.

#### Write-back statuses

A write-back that does not go through never undoes the document change. It is only reported.

| `status` | Meaning |
| -------- | ------- |
| `applied` | The template or knowledge base entry now has the change |
| `not_allowed` | Your role cannot change templates or org-wide knowledge base entries |
| `not_supported` | This kind of change cannot go there. A `new_section` change cannot be copied into the template, and only a `kb_clause` change can be copied into the knowledge base |
| `refused` | The change could not be written safely: the target changed since the document was generated, or the change would remove a template field (as a `value` change does). `message` says which case it is |

`refused` messages you can get:

- `The template changed since this document was generated, so this change was not applied to it. It can still be kept on this document only.`
- `This change would remove a field from the template (FIELD_NAME), so it was not applied. It can still be kept on this document only.`
- `The knowledge base entry no longer contains this wording word for word, so it was not changed. It can still be kept on this document only.`

A `kb_clause` change copied back with `"writeBack": "kb"` returns:

```json
{
  "data": {
    "results": {
      "deliverable": { "id": "ddcb7097-b0fd-4416-835c-0486c1a75cc7", "name": "Agreement - Gamma" },
      "applied": 1,
      "write_backs": [
        { "change_id": "c1", "target": "kb", "status": "applied" }
      ]
    }
  }
}
```

Every template that uses that entry's field picks up the new wording the next time it generates.

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `ValidationError` | `"decisions" must contain at least 1 items` (in `data.errors`) |
| `400` | `DocumentHasNewerVersion` | Before I apply it, I noticed this document has a newer version than the copy that was reviewed. Compare the reviewed copy with the newer version, or stop here? |
| `403` | | `Forbidden`: your role cannot generate documents |
| `404` | `RedlineReviewNotFound` | That review was not found, or it was already decided. |

A review can be applied once. A second call returns `404 RedlineReviewNotFound`. Do not send the same apply request twice at the same time; wait for the first response.

## Endpoint 3: Check a Knowledge Base Entry for Drift

For one knowledge base entry, list the templates that follow it through its field, and the templates that hold a pasted copy of its text instead. A pasted copy does not update when the entry changes, so it can drift.

### Endpoint

```http
GET https://api.turbodocx.com/v1/knowledge-base/:variableMapId/drift
```

### Path Parameters

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `variableMapId` | String (UUID) | **Yes** | The knowledge base entry. It is the `variableMapId` that [Read Variables](./read-variables-folder.api.mdx) returns with `isGlobal=true` or a `templateFolderId` |

An org-wide entry is checked against every template in your organization. A folder entry is checked against the templates in its folder. Only Word templates are read, up to 200 per check.

### Example Request

```bash
curl "https://api.turbodocx.com/v1/knowledge-base/VARIABLE_MAP_ID/drift" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID"
```

### Response

`200 OK`. Here one template holds a copy of the clause that says "five years" where the entry says "three years":

```json
{
  "data": {
    "results": {
      "entry": {
        "variableMapId": "1e023f0d-aa7e-4ea4-9aa4-02b98a4ac0cf",
        "name": "Confidentiality clause",
        "placeholder": "{confidentiality_clause}"
      },
      "usedBy": [],
      "copies": [
        {
          "templateId": "1910b7e5-b2a6-4bc9-bb82-ac6ae56bfb4b",
          "name": "Services Agreement",
          "paragraphIds": ["body:3"],
          "text": "Each party shall keep the other party's confidential information secret for five years and use it only to perform this agreement.",
          "similarity": 0.9523809523809523,
          "exact": false
        }
      ],
      "scanned": 1,
      "truncated": false
    }
  }
}
```

### Response Fields

| Field | Type | Description |
| ----- | ---- | ----------- |
| `entry` | Object | The entry: `variableMapId`, `name` and `placeholder` |
| `usedBy` | Array | Templates that use the entry's field, so they follow it: `templateId` and `name` |
| `copies` | Array | Pasted copies of the entry's text found in templates |
| `copies[].templateId`, `copies[].name` | String | The template holding the copy |
| `copies[].paragraphIds` | Array | The paragraphs the copy covers |
| `copies[].text` | String | The copy's text, as it is in the template. Send it to [Swap](#endpoint-4-swap-a-copy-for-the-entrys-field) |
| `copies[].similarity` | Number | How close the copy is to the entry, from `0.6` to `1`. Text below `0.6` is not reported |
| `copies[].exact` | Boolean | `true` when the copy is word for word the same. It has not drifted yet, but it will not follow future changes |
| `scanned` | Number | How many templates were read |
| `truncated` | Boolean | `true` when there were more than 200 templates and the rest were not read |

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `ValidationError` | `"variableMapId" must be a valid GUID` (in `data.errors`) |
| `403` | | `Forbidden` |
| `404` | `KnowledgeBaseEntryNotFound` | That knowledge base entry was not found. |

A variable that belongs to a single template is not a knowledge base entry and returns `404`.

## Endpoint 4: Swap a Copy for the Entry's Field

Replace a pasted copy in a template with the entry's field, so the template follows the entry from now on.

### Endpoint

```http
POST https://api.turbodocx.com/v1/knowledge-base/:variableMapId/drift/swap
```

### Path Parameters

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `variableMapId` | String (UUID) | **Yes** | The knowledge base entry |

### Request Body (JSON)

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `templateId` | String (UUID) | **Yes** | The template holding the copy, from `copies[].templateId` |
| `text` | String | **Yes** | The exact text to replace, from `copies[].text`. 1 to 20,000 characters |
| `placeholder` | String | **Yes** | The field to put in its place, normally the entry's `placeholder`, such as `{confidentiality_clause}`. 3 to 120 characters |

### Example Request

```bash
curl -X POST "https://api.turbodocx.com/v1/knowledge-base/VARIABLE_MAP_ID/drift/swap" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "templateId": "TEMPLATE_ID",
    "text": "Each party shall keep the other party'\''s confidential information secret for five years and use it only to perform this agreement.",
    "placeholder": "{confidentiality_clause}"
  }'
```

### Response

`200 OK`:

```json
{
  "data": {
    "results": {
      "recordId": "c1da885c-3db8-4be8-a430-95c5182f6915",
      "newSha256": "00e9ae58006ec603cdfc3a20f9f62a8c47793d873cd714b33c84b011376803a7"
    }
  }
}
```

| Field | Type | Description |
| ----- | ---- | ----------- |
| `recordId` | String | The ID of the saved change record. TurboDocx keeps the template's previous file with it |
| `newSha256` | String | The SHA-256 hash of the template's new file |

Run the drift check again and the template moves from `copies` to `usedBy`.

:::caution Send the clause when you generate from this template
After a swap, the template has a field where the clause used to be. When you [create a deliverable](./Deliverable-API.md#endpoint-2-create-deliverable) through the API, send the entry's text as that field's value. If you leave it out, the clause renders empty and the response's `placeholderReport.missing` lists the field.
:::

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `TemplateChanged` | The template changed since this document was generated, so this change was not applied to it. It can still be kept on this document only. |
| `400` | `TemplateWouldLoseField` | This change would remove a field from the template (FIELD_NAME), so it was not applied. It can still be kept on this document only. |
| `400` | `ValidationError` | A missing or invalid body field (in `data.errors`) |
| `403` | | `Forbidden`: only administrators and contributors can change a template |
| `404` | `TemplateNotFound` | That template was not found. |

`TemplateChanged` here means `text` was not found in the template word for word. Run the drift check again and copy `copies[].text` exactly. Nothing is written when the swap is refused.

## Endpoint 5: Upload a Document

Upload a Word or PDF file once, and use its `upload_id` with the template endpoints below.

### Endpoint

```http
POST https://api.turbodocx.com/v1/assistant/uploads
```

### Request Body (multipart/form-data)

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `file` | File | **Yes** | A .docx or .pdf file, up to 25 MB |

### Example Request

```bash
curl -X POST "https://api.turbodocx.com/v1/assistant/uploads" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -F "file=@./services-agreement.docx"
```

### Response

`201 Created`:

```json
{
  "data": {
    "results": {
      "upload_id": "4efc8ee9-378b-4759-ba71-7e4a8d53ad09",
      "filename": "services-agreement.docx",
      "media_type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "size_bytes": 1786,
      "kind": "docx"
    }
  }
}
```

| Field | Type | Description |
| ----- | ---- | ----------- |
| `upload_id` | String | Send it as `uploadId` to the endpoints below |
| `filename` | String | The file name you sent |
| `media_type` | String | The file's type |
| `size_bytes` | Number | The file's size |
| `kind` | String | `docx` or `pdf` |
| `pages` | Number | For a PDF: its page count |

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `NoFile` | No file uploaded under field 'file'. |
| `400` | `UnsupportedFileType` | Only Word (.docx) and PDF files can be attached. |
| `400` | `LIMIT_FILE_SIZE` (in `code`) | File size exceeds the maximum allowed size of 25MB. Please upload a smaller file. |

Only a .docx can become a template. A PDF uploads fine but is refused by the next two endpoints.

## Endpoint 6: Suggest Fields

Read an uploaded Word document and suggest which values should become template fields: names, dates, amounts, addresses and similar. This uses TurboDocx AI and costs AI credits.

### Endpoint

```http
POST https://api.turbodocx.com/v1/templates/from-document/suggest
```

### Request Body (JSON)

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `uploadId` | String (UUID) | **Yes** | The `upload_id` of a .docx |

### Example Request

```bash
curl -X POST "https://api.turbodocx.com/v1/templates/from-document/suggest" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -H "Content-Type: application/json" \
  -d '{ "uploadId": "UPLOAD_ID" }'
```

### Response

`200 OK`:

```json
{
  "data": {
    "results": {
      "fields": [
        { "find": "TurboDocx", "variable": "party_one" },
        { "find": "Acme Corporation", "variable": "party_two" },
        { "find": "5000 USD per month", "variable": "fee_amount" },
        { "find": "1 March 2026", "variable": "start_date" },
        { "find": "Paris", "variable": "signing_location" }
      ]
    }
  }
}
```

| Field | Type | Description |
| ----- | ---- | ----------- |
| `fields` | Array | Up to 60 suggestions. Each `find` is text copied exactly from the document, and each `variable` is a valid field name in snake_case |

Suggestions are only a starting point. Remove the ones you do not want, rename fields, and send the list to [Create a Template](#endpoint-7-preview-or-create-a-template-from-a-document) as `variables`. Signature lines are not suggested here; they are found when you preview or create. The suggestions can differ between calls.

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `TemplatizeNeedsDocx` | Only a Word file (.docx) can be turned into a template. |
| `402` | `InsufficientCredits` | Insufficient AI credits. These tasks require N credits, but you have M credits available. Please purchase more credits to continue. |
| `403` | | `Forbidden`: your plan does not include TurboDocx AI, or your role cannot create templates |
| `404` | `AttachmentNotFound` | That attachment was not found. Check the upload_id, or attach the file again. |

## Endpoint 7: Preview or Create a Template from a Document

Turn an uploaded Word document into a template. Each `find` text you list becomes a field. Run it with `"mode": "preview"` to check the result, then with `"mode": "create"` to save the template.

### Endpoint

```http
POST https://api.turbodocx.com/v1/templates/from-document
```

### Request Body (JSON)

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| `uploadId` | String (UUID) | **Yes** | The `upload_id` of a .docx |
| `name` | String | **Yes** | The template's name, 1 to 255 characters |
| `mode` | String | **Yes** | `preview` to check the result without saving a template, `create` to save it |
| `variables` | Array | **Yes** | Up to 200 fields to place. Can be `[]` |
| `variables[].find` | String | **Yes** | Text to replace, copied exactly from the document (up to 2,000 characters) |
| `variables[].variable` | String | **Yes** | The field name, such as `client_name`. It is turned into snake_case |
| `variables[].context` | String | No | Nearby words, to pick the right place when `find` appears more than once (up to 200 characters) |
| `variables[].paragraph_ids` | Array | No | Only replace in these paragraphs, such as `["body:2"]` (up to 50) |
| `variables[].occurrence` | Number | No | Only replace the nth match, from 1 to 50 |
| `skipSignatureAnchors` | Array | No | Signature anchors to leave out, by name, from the ones found in the document |

`create` rebuilds from the original upload with the same body, so a preview never changes what create does. Send the same body with only `mode` changed.

Signature lines in the document, such as `Signature: ____` and `Date: ____` under a party's name, become signature anchors automatically. They are listed in `signature_anchors`, and the template is then ready for [TurboSign](../TurboSign/API-Signatures.md). Leave one out with `skipSignatureAnchors`.

### Example Request

```bash
curl -X POST "https://api.turbodocx.com/v1/templates/from-document" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "uploadId": "UPLOAD_ID",
    "name": "Services Agreement",
    "mode": "preview",
    "variables": [
      { "find": "Acme Corporation", "variable": "client_name" },
      { "find": "5000 USD per month", "variable": "fee_amount" },
      { "find": "1 March 2026", "variable": "start_date" },
      { "find": "Lisbon", "variable": "city" }
    ]
  }'
```

### Response (preview)

`200 OK`. `Lisbon` is not in the document, so it is reported in `not_found`:

```json
{
  "data": {
    "results": {
      "mode": "preview",
      "preview_upload_id": "b8be2cbe-9fdc-418d-bfe0-4adfdbd526bc",
      "placed": [
        { "find": "5000 USD per month", "variable": "fee_amount", "paragraphId": "body:2", "matched": "5000 USD per month" },
        { "find": "Acme Corporation", "variable": "client_name", "paragraphId": "body:1", "matched": "Acme Corporation" },
        { "find": "1 March 2026", "variable": "start_date", "paragraphId": "body:2", "matched": "1 March 2026" }
      ],
      "existing_fields": [],
      "adjusted": [],
      "adjusted_capped": false,
      "not_found": [
        { "find": "Lisbon", "variable": "city", "reason": "not_found", "message": "\"Lisbon\" does not appear in the document." }
      ],
      "name_problems": [],
      "same_value_warnings": [],
      "problems": [],
      "signature_anchors": [],
      "ready": true
    }
  }
}
```

To see the preview, download it as a PDF:

```bash
curl "https://api.turbodocx.com/v1/assistant/uploads/PREVIEW_UPLOAD_ID/preview" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  --output preview.pdf
```

### Response (create)

`201 Created`. The same report, plus the new template:

```json
{
  "data": {
    "results": {
      "mode": "create",
      "template_id": "1a8bf679-935a-4ef7-a684-f03715348c6a",
      "name": "Services Agreement",
      "file_sha256": "c0cc58b3e05fefef1bfc4b43032c3e403c80a0d999f05d0da67343ac4ada9873",
      "placed": [ "..." ],
      "not_found": [ "..." ],
      "signature_anchors": [],
      "ready": true
    }
  }
}
```

The new template has one field per placed variable, here `{client_name}`, `{fee_amount}` and `{start_date}`. Use `template_id` with [Create Deliverable](./Deliverable-API.md#endpoint-2-create-deliverable).

### Response Fields

| Field | Type | Description |
| ----- | ---- | ----------- |
| `mode` | String | `preview` or `create` |
| `preview_upload_id` | String | Preview only: the built document, as an upload. Download it as a PDF from `/v1/assistant/uploads/:id/preview` |
| `template_id`, `name` | String | Create only: the new template |
| `file_sha256` | String | Create only: the SHA-256 hash of the template's file |
| `placed` | Array | Each field placed: `find`, `variable`, the `paragraphId` it landed in, and the text it `matched` |
| `existing_fields` | Array | Fields the document already had, written as `{name}`: `variable` and how many paragraphs (`places`) carry it |
| `adjusted` | Array | Fields already in the document that were fixed (for example renamed to a valid name) or left as plain text, and anything unsafe that was removed |
| `adjusted_capped` | Boolean | `true` when there were more than 200 to fix and the rest were left as written |
| `not_found` | Array | Entries in `variables` that could not be placed, each with a `message` |
| `name_problems` | Array | Field names that could not be used |
| `same_value_warnings` | Array | The same text mapped to different fields, or one field given different texts. Check each place got the right one |
| `problems` | Array | Problems that stop the document from working as a template |
| `signature_anchors` | Array | Signature anchors added, by name |
| `ready` | Boolean | `true` when the document works as a template. `create` only succeeds when it is `true` |

`ready` only looks at whether the template can be read. A template is still created when some entries are in `not_found`, so check that list before you rely on a field.

For example, a document with a `Client` heading followed by `Signature: ____` and `Date: ____` returns:

```json
{
  "signature_anchors": ["client_signature", "client_sign_date"],
  "same_value_warnings": [
    {
      "find": "______________________",
      "kind": "different_variables",
      "variables": ["client_signature", "client_sign_date"],
      "message": "\"______________________\" is mapped to client_signature and client_sign_date. Check each place got the right one."
    }
  ]
}
```

### Errors

| Status | `type` | Message you get |
| ------ | ------ | --------------- |
| `400` | `ValidationError` | A missing or invalid body field, such as `"mode" is required` (in `data.errors`) |
| `400` | `TemplatizeNeedsDocx` | The upload is a PDF. Upload the Word file instead |
| `400` | `DocumentHasTrackedChanges` | The document has tracked changes. Accept or reject the changes in Word first, then upload it again. |
| `400` | `TemplateNotReady` | Create only: nothing was created because the document cannot be read as a template. The message gives the reason |
| `400` | `Insufficient...` | Create only: your organization reached its template or storage limit for its plan |
| `403` | | `Forbidden`: your role cannot create templates |
| `404` | `AttachmentNotFound` | That attachment was not found. Check the upload_id, or attach the file again. |

## Complete Workflow: A Contract Comes Back

```bash
# 1. Compare the returned copy
curl -X POST "https://api.turbodocx.com/v1/redline/reviews" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -F "file=@./agreement-returned.docx"
# -> data.results.review_id and data.results.changes

# 2. Accept what you agree with; send fixed-wording fixes to the template too
curl -X POST "https://api.turbodocx.com/v1/redline/reviews/REVIEW_ID/apply" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  -H "Content-Type: application/json" \
  -d '{ "decisions": [ { "changeId": "c1", "accept": true }, { "changeId": "c2", "accept": true, "writeBack": "template" } ] }'
# -> data.results.deliverable.id is the new version's ID

# 3. Download the new version
curl "https://api.turbodocx.com/v1/deliverable/file/NEW_DELIVERABLE_ID" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "x-rapiddocx-org-id: YOUR_ORGANIZATION_ID" \
  --output agreement-v2.docx
```

## Error Response Format

Most errors from these endpoints look like this:

```json
{
  "message": "That review was not found, or it was already decided.",
  "type": "RedlineReviewNotFound"
}
```

Branch on `type`, and show `message` to people. Body validation errors use `type: "ValidationError"` and list each problem in `data.errors`. A missing or wrong API key returns `401` with the body `Unauthorized`. A role or plan that is not allowed returns `403` with the body `Forbidden`.
